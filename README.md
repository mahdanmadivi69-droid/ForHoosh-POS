# SmartOrders POS (اسمارت‌اوردرز) — کافه ۱۰۰هیچ

> **دامنه واقعی این نسخه (Pilot Scope):** یک **پایلوت محلی تک‌صندوقه** برای شعبه ۱۰۰هیچ.
> هستهٔ کارآمد، صندوق فروش (POS) در یک مرورگر/یک دستگاه است. قابلیت‌های «چندمستأجری»،
> «PostgreSQL + RLS»، «وب‌سوکت بلادرنگ» و «کسر رسپی/BOM» **پیاده‌سازی نشده‌اند** و در این
> نسخه فقط نمونهٔ اولیه/نقشهٔ راه هستند. برای جزئیات به [وضعیت پروژه](./PROJECT_STATUS.md)
> مراجعه کنید. این README عمداً هیچ قابلیت تأییدنشده‌ای را «تأییدشده» اعلام نمی‌کند.

---

## چه چیزی در این نسخه کار می‌کند

- **صندوق فروش (POS):** انتخاب اقلام، تخفیف، تسویه نقدی/کارتخوان، محاسبهٔ باقی‌مانده و پیش‌نمایش فیش.
- **شیفت و گزارش مالی:** باز/بسته کردن شیفت، مغایرت صندوق نقد، کارت سود عملیاتی شیفت، خروجی CSV سفارش‌ها و هزینه‌ها.
- **مدیریت منو:** ویرایش قیمت و موجودی اقلام.
- **لاگ حسابرسی محلی:** ثبت رخدادهای اصلی در همان مرورگر.
- **ذخیره‌سازی محلی:** LocalStorage مرجع همگام و اصلی است؛ **سفارش‌ها** علاوه بر آن در
  IndexedDB (Dexie، دیتابیس `CafeOS_LocalDB`، جدول `posOrders`) آینه می‌شوند تا با پاک‌شدن/پرشدن
  LocalStorage از دست نروند (مهاجرت کامل داده‌ها انجام نشده است — پایین را ببینید).
- **چاپ حرارتی ۸۰ میلی‌متری:** چاپ از طریق iframe و درایور ESC/POS (WebUSB/Web Bluetooth)
  پیاده‌سازی شده اما **روی سخت‌افزار واقعی تأیید نشده** است.

## محدودیت‌ها و چیزهایی که هنوز ساخته نشده‌اند

| ادعای رایج | واقعیت این نسخه |
|---|---|
| PostgreSQL + RLS / چندمستأجری | فقط یک DDL متنی و یک انبار **در حافظه**؛ هیچ اتصال `pg` یا `DATABASE_URL` وجود ندارد و RLS اجرا نمی‌شود. |
| سرور Express چندمستأجره | روت‌های `/api/v1/*` در حافظهٔ RAM کار می‌کنند، احراز هویت/مجوز سمت سرور ندارند و با ری‌استارت پاک می‌شوند. |
| وب‌سوکت بلادرنگ | یک `EventEmitter` + `BroadcastChannel` درون‌فرایندی است؛ کلاینت سوکت واقعی وجود ندارد. «بلادرنگ» فقط در همان تب/مرورگر معنا دارد. |
| BOM / کسر رسپی مواد اولیه | سرویس `orderService.ts` و جداول Dexie آن به مسیر اجرایی متصل نیستند (dead code). کسر موجودی واقعی، شمارندهٔ هر آیتم منو است. |
| مودال PIN مدیر | کامپوننت `OrderActionModal` هیچ import‌کننده‌ای ندارد و PIN `1234` در باندل است. |
| اسکن/لاگین امن | رمزها به‌صورت plaintext ذخیره و مقایسه می‌شوند؛ دکمه‌های ورود یک‌کلیکی امنیت را دور می‌زنند. (اصلاح در فاز ۲) |
| Zero-G (سامانهٔ مافوق سریع) | نمونهٔ اولیه است و به‌صورت **پیش‌فرض خاموش** است. برای فعال‌سازی آگاهانه: `VITE_ENABLE_ZERO_G_SMART_ORDERS=true` در فایل `.env`. تسویه در آن بدون سفارش و پرداخت ماندگار، موفقیت اعلام نمی‌کند. |
| «۲۲۶ تست» / «Zero TS Errors» | دو اسکریپت دستی assert-محور (بدون فریم‌ورک) وجود دارد و اجرای آن‌ها در این نسخه مستقل تأیید نشده است. `tsconfig` غیرسخت‌گیرانه است. |

> **مهاجرت ناقص ذخیره‌سازی (P0-2):** در پایش فاز ۱ فقط **سفارش‌ها** به Dexie آینه می‌شوند
> (snapshot کامل در هر ذخیره). `payments`، `shifts`، `expenses`، `users` و `auditLogs` هنوز
> فقط در LocalStorage هستند. مهاجرت کامل و تراکنشی، کار فازهای بعدی است.

## راه‌اندازی و اجرا

### ۱. اجرای سریع در ویندوز (۱-کلیک)
- فایل `RUN_100HICH.bat` را اجرا کنید تا برنامه راه‌اندازی شده و خودکار در مرورگر باز شود.
- جهت نصب اولیه پیش‌نیازها از `INSTALL_100HICH.bat` استفاده کنید.

### ۲. اجرای دستی از طریق ترمینال
```bash
# نصب وابستگی‌ها
npm install --legacy-peer-deps

# اجرای اسکریپت‌های بررسی حسابداری (دو اسکریپت assert-محور؛ فریم‌ورک تست نیست)
npm test

# بررسی تایپ‌اسکریپت
npm run lint

# اجرای سرور توسعه (پورت پیش‌فرض ۳۰۰۱؛ با متغیر PORT قابل تغییر است)
npm run dev

# ساخت نسخهٔ PWA
npm run build
```

> **هشدار دپلوی:** خروجی استاتیک (GitHub Pages) نمی‌تواند روت‌های `/api/v1/*` را سرو کند؛
> روی هاست استاتیک، صف همگام‌سازی هر سفارش را `FAILED` می‌کند. این نسخه برای اجرای
> **محلی/آفلاین** طراحی شده است، نه به‌عنوان SaaS چنددستگاهی.
