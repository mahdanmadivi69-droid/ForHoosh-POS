# معماری سیستم و پشته فنی (ARCHITECTURE) — SmartOrders

## ۱. اهداف کلیدی معماری
1. **پایداری عملیاتی بدون وقفه:** کارکرد بدون قطعی حتی در شرایط نوسان اتصال اینترنت در کافه.
2. **صفر کردن هزینه اولیه میزبانی:** انطباق کامل با سقف بودجه ۳۰۰ دلاری برای ۹۰ روز نخست.
3. **انزوا و ایزولاسیون چندمستأجری (Tenant Isolation):** هر درخواست و هر رکورد پایگاه داده با کلید `tenant_id` مقید می‌شود.
4. **دقت ریاضیات پولی:** استفاده انحصاری از اعداد صحیح با واحد تومان، پیاده‌سازی متدهای خالص محاسباتی و تست‌پذیری کامل.

## ۲. لایه‌بندی نرم‌افزار (Tiered Architecture)
```
+-------------------------------------------------------------+
|                     لایه ارائه (Client PWA)                 |
|  - React 19 + TypeScript + Tailwind CSS (v4) + Vite         |
|  - رابط صندوق کاربری لمسی و فوق‌سریع (Persian RTL)           |
|  - موتور محاسبات ریاضیات مالی (Zero-Float Precision Engine)  |
|  - لایه کش و ذخیره‌سازی محلی برای حفظ پایداری و بازیابی خطا |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|                      لایه API و منطق تجاری                  |
|  - کنترل دسترسی بر اساس نقش (RBAC): مالک، مدیر، صندوق‌دار   |
|  - تراکنش‌های اتمیک باز و بسته کردن شیفت                   |
|  - ثبت غیرقابل بازگشت سوابق مالی و لاگ حسابرسی             |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|                  پایگاه داده رابطه‌ای (PostgreSQL)           |
|  - پشتیبانی از تراکنش‌های ACID                              |
|  - کلیدهای خارجی و محدودیت‌های اعتبارسنجی (CHECK constraints)|
+-------------------------------------------------------------+
```

## ۳. امنیت و جداسازی مستأجرها (Multi-Tenancy Security)
- تفکیک منطقی از طریق فیلد `tenant_id` در تمامی جداول.
- هیچ کوئری یا اکشنی مجاز به دریافت یا ویرایش داده بدون فیلتر `tenant_id` نیست.
- سشن کاربر حامل توکن با امضای دیجیتال حاوی `tenant_id` و `user_id` و `role` است.
