## ۱. بیانیه معماری و اصل Single Source of Truth

در این پروژه، منطق پیچیده حسابداری، فرمولاسیون رسپی و کسر متریال انبار (BOM Engine)، سیستم حساب باز میزها (Open Tabs)، تفکیک تیکت‌های بار و آشپزخانه (Station Router)، چاپگرهای حرارتی ESC/POS، گیت امنیتی RBAC، و محاسبات تراز صندوق در قالب یک **هسته مشترک (Shared Core)** توسعه یافته و نگهداری می‌شوند.

برای هر دو مشتری تجاری:
1. **کافه بردگیم و گیمینگ مودندو (`tenant-modendo-01`)**
2. **قهوه‌فروشی تخصصی ۱۰۰هیچ (`tenant-100hich-01`)**

استقرارها، پایگاه‌های داده لوکال، تنظیمات سخت‌افزاری، کاتالوگ و کلیدهای ذخیره‌سازی به‌صورت ۱۰۰٪ ایزوله و بدون هیچ‌گونه نشت متقابل عمل می‌کنند.


## ۲. مکانیسم تفکیک کامل داده‌ها (Data Isolation Engine)

### ۲.۱. کلیدهای ذخیره‌سازی محلی (Tenant-Scoped Storage Keys)
برای جلوگیری از تداخل داده‌ها در صورت اجرای هر دو نسخه روی یک مرورگر واحد، کلیدهای حافظه بر اساس شناسه تننت تفکیک شده‌اند:

| نهاد داده | کلید اختصاصی کافه مودندو | کلید اختصاصی کافه ۱۰۰هیچ |
| :--- | :--- | :--- |
| **شیفت‌های کاری** | `smartorders_shifts_tenant-modendo-01_v1` | `smartorders_shifts_tenant-100hich-01_v1` |
| **سفارشات و فاکتورها** | `smartorders_orders_tenant-modendo-01_v1` | `smartorders_orders_tenant-100hich-01_v1` |
| **تراکنش‌های پرداخت** | `smartorders_payments_tenant-modendo-01_v1` | `smartorders_payments_tenant-100hich-01_v1` |
| **هزینه‌های تنخواه** | `smartorders_expenses_tenant-modendo-01_v1` | `smartorders_expenses_tenant-100hich-01_v1` |
| **دفتر کل حسابرسی** | `smartorders_audit_logs_tenant-modendo-01_v1` | `smartorders_audit_logs_tenant-100hich-01_v1` |
| **نقشه سالن** | `modendo_floor_plan_v6.3` | `100hich_floor_plan_v1.0` |
| **پروفایل سخت‌افزار** | پروفایل‌های پرینتر LAN مودندو | پروفایل‌های پرینتر سریال/وب‌سوکت ۱۰۰هیچ |

### ۲.۲. ایزولاسیون دیتابیس IndexedDB و PostgreSQL
- **IndexedDB:** رکوردهای پیکربندی و درایورهای سخت‌افزاری بر اساس Tenant ID تفکیک شده‌اند.
- **PostgreSQL Backend Contract:** اعمال سیاست‌های امنیت سطحی ردیف (Row-Level Security):
  ```sql
  SET LOCAL app.current_tenant_id = 'tenant-modendo-01';
  ```
